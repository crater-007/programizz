TASK 2: BANKER'S ALGORITHM IMPLEMENTATION

Aim
To implement Dijkstra's Banker's Algorithm for resource allocation, checking whether the system is in a safe state and deciding whether a new resource request can be granted safely.

Theory
Banker's Algorithm is a deadlock-avoidance algorithm used by an operating system. Before allocating resources, it checks whether the allocation will leave the system in a safe state.

A safe state is a state in which there is at least one sequence of process execution that allows every process to finish with the available resources and the resources released by completed processes.

Important Data Structures
1. Available: Number of currently available instances of each resource type.
2. Max: Maximum number of resources each process may require.
3. Allocation: Number of resources currently allocated to each process.
4. Need: Number of additional resources required by each process.

Need = Max - Allocation

Safety Algorithm
1. Set Work equal to Available.
2. Mark every process as unfinished.
3. Find an unfinished process whose Need is less than or equal to Work for every resource type.
4. If such a process is found, add its Allocation to Work and mark it finished.
5. Repeat until all processes are finished or no suitable process can be found.
6. If all processes finish, the system is safe. Otherwise, it is unsafe.

Resource Request Algorithm
1. Read the requesting process and its request vector.
2. Check whether Request is less than or equal to Need.
3. Check whether Request is less than or equal to Available.
4. Temporarily allocate the requested resources.
5. Run the safety algorithm.
6. If the system remains safe, grant the request.
7. Otherwise, restore the previous allocation and deny the request.

Conclusion
Banker's Algorithm avoids unsafe resource allocations by checking the system's safety before granting a request. It helps prevent deadlocks by ensuring that the system remains in a safe state.
