TASK 1: SEMAPHORE IMPLEMENTATION
BOUNDED BUFFER / PRODUCER-CONSUMER PROBLEM

1. Aim
To implement the bounded-buffer Producer-Consumer problem using POSIX
semaphores and Pthreads in C++.

2. Theory
The Producer-Consumer problem is a classic process synchronization problem.
A producer creates items and places them in a shared buffer. A consumer
takes items from that buffer. Since both may access the buffer concurrently,
synchronization is required to prevent race conditions.

The buffer has a fixed capacity N. In this program, N is 5.

Three semaphores are used:

a) mutexSem
   - A binary semaphore initialized to 1.
   - Ensures that only one thread accesses the shared buffer at a time.
   - Protects the critical section.

b) emptySlots
   - A counting semaphore initialized to N.
   - Represents the number of empty positions in the buffer.
   - A producer waits on it before inserting an item.

c) fullSlots
   - A counting semaphore initialized to 0.
   - Represents the number of filled positions in the buffer.
   - A consumer waits on it before removing an item.

3. Working

Producer:
   1. Wait for an empty buffer position.
   2. Acquire the mutex semaphore.
   3. Insert an item into the buffer.
   4. Move the insertion index circularly.
   5. Release the mutex semaphore.
   6. Signal that one more slot is full.

Consumer:
   1. Wait until at least one buffer position is full.
   2. Acquire the mutex semaphore.
   3. Remove an item from the buffer.
   4. Move the removal index circularly.
   5. Release the mutex semaphore.
   6. Signal that one more slot is empty.

The buffer is implemented as a circular queue. The modulo operation keeps
the insertion and removal indexes within the buffer boundaries.

4. Important Concepts
- Race condition: An unwanted result caused by unsynchronized concurrent
  access to shared data.
- Critical section: The part of a program that accesses shared resources.
- Semaphore: A synchronization variable controlled using wait and signal
  operations.
- Pthread: POSIX thread library used to create and manage threads.
- Circular buffer: A fixed-size buffer in which indexes wrap around.

5. Initial Semaphore Values
   mutexSem = 1
   emptySlots = 5
   fullSlots = 0

6. Expected Result
Two producer threads generate a total of 10 items. Two consumer threads
remove those 10 items. Producers wait if the buffer is full, and consumers
wait if it is empty. The program terminates after all items are consumed.

7. Compilation and Execution
Save the source file as producer_consumer.cpp.

Compile:
   g++ -std=c++17 producer_consumer.cpp -o producer_consumer -pthread

Run:
   ./producer_consumer

8. Viva Questions

Q1. What is a semaphore?
A. A semaphore is a synchronization mechanism used to control access to
   shared resources through wait and signal operations.

Q2. Why are three semaphores used?
A. mutex protects the critical section, empty tracks free slots, and full
   tracks occupied slots.

Q3. What is the initial value of the empty semaphore?
A. It is initialized to the buffer capacity, which is 5 here.

Q4. What is the initial value of the full semaphore?
A. It is initialized to 0 because the buffer starts empty.

Q5. What is a race condition?
A. It occurs when the result depends on the unpredictable timing of
   concurrent threads accessing shared data.

Q6. What is the difference between binary and counting semaphores?
A. A binary semaphore generally uses values 0 and 1, while a counting
   semaphore tracks multiple available instances of a resource.
