TASK 1: CONCURRENT DEADLOCK SIMULATION

Aim
To demonstrate a deadlock situation between two threads using two shared mutex locks and then prevent it by following a fixed lock acquisition order.

Theory
A thread is a small unit of execution within a process. When multiple threads access shared resources, mutex locks are used to ensure that only one thread accesses a protected resource at a time.

A deadlock occurs when two or more threads wait indefinitely for resources held by one another. In this program, Thread_1 first acquires MutexA and Thread_2 first acquires MutexB. Both threads wait for 100 milliseconds and then request the lock held by the other thread.

The program uses timed mutex locks. Each thread waits for the second lock for a limited time. This demonstrates the blocked state without allowing the program to remain stuck forever.

Four Necessary Conditions for Deadlock
1. Mutual Exclusion: A resource can be held by only one thread at a time.
2. Hold and Wait: A thread holds one resource while waiting for another.
3. No Preemption: A resource cannot be forcibly taken from a thread.
4. Circular Wait: Thread_1 waits for MutexB while Thread_2 waits for MutexA.

Deadlock Prevention
The deadlock is prevented by making both threads acquire the locks in the same order: MutexA followed by MutexB. This removes the circular-wait condition and allows both threads to finish.

Algorithm
1. Create two shared timed mutex locks, MutexA and MutexB.
2. Start Thread_1 and Thread_2.
3. Thread_1 acquires MutexA, while Thread_2 acquires MutexB.
4. Synchronize the threads so both have acquired their first lock.
5. Wait for 100 milliseconds.
6. Each thread requests the lock held by the other thread.
7. Use a limited waiting time to demonstrate blocking without hanging the program.
8. Release the first locks after the timed requests fail.
9. Start the corrected execution in which both threads acquire MutexA first and MutexB second.
10. Join both threads and display the completion message.

Conclusion
The program demonstrates how two threads can enter a deadlock-like waiting situation when they acquire shared locks in opposite orders. Using a fixed lock acquisition order prevents circular wait and allows normal completion.

Compilation
