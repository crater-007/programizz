============================================================ 1.
INTRODUCTION TO OPERATING SYSTEM FILE MANAGEMENT
============================================================

An operating system (OS) is system software that manages computer
hardware and provides services to application programs. One important
responsibility of an OS is file-system management.

A file system organizes data on storage devices such as hard disks,
SSDs, and USB drives. It allows users and programs to create, read,
write, rename, and delete files and directories.

A file is a named collection of data stored on secondary storage. A
directory is a special file-system structure used to organize and locate
files and other directories.

The operating system provides interfaces that programs can use to
request file-system operations. On POSIX-compatible systems (such as
Linux and Unix), many of these interfaces are system calls.

The four practical tasks in this assignment demonstrate: - Copying file
contents using low-level system calls. - Retrieving file metadata. -
Reading directory entries. - Simulating the way indexed allocation
assigns disk blocks to files.

  ----------------------------
  1.1 What is a System Call?
  ----------------------------

A system call is a controlled interface through which a user program
requests a service from the operating-system kernel.

Applications normally run in user mode and cannot directly perform
privileged operations on hardware or kernel-managed resources. When a
program needs an OS service, it makes a system call. The kernel performs
the requested operation and returns a result.

Examples of file-related POSIX system calls: - open(): open a file or
create one. - read(): read bytes from a file descriptor. - write():
write bytes to a file descriptor. - close(): close a file descriptor. -
stat(): obtain file metadata. - lstat(): obtain metadata about a
symbolic link itself. - lseek(): change the current file offset. -
unlink(): remove a file name from the file system.

System calls generally return a value indicating success or failure. For
many calls, -1 indicates failure and errno is set to describe the error.

  -------------------------------------------------
  1.2 System Calls vs. Standard Library Functions
  -------------------------------------------------

A system call provides a kernel service. A standard library function is
a higher-level programming interface supplied by a library.

Examples: - open() is a POSIX system call interface; fopen() is a C
standard I/O library function. - read() reads bytes from a file
descriptor; fread() reads items through a FILE stream. - write() writes
bytes to a file descriptor; fwrite() writes items through a FILE
stream. - close() closes a file descriptor; fclose() closes a FILE
stream.

The standard I/O functions often provide buffering and additional
convenience. Low-level file-descriptor operations give the programmer
more direct control over byte-level input and output.

For this assignment, mycp uses open(), read(), write(), and close()
instead of fopen(), fread(), fwrite(), and fclose().

  ----------------------
  1.3 File Descriptors
  ----------------------

A file descriptor is a small non-negative integer used by a process to
refer to an open file or another I/O resource.

When a process starts, the usual standard file descriptors are: - 0 –
Standard input (stdin) - 1 – Standard output (stdout) - 2 – Standard
error (stderr)

The open() function returns a new file descriptor when it succeeds.
Other calls such as read(), write(), and close() use that descriptor to
identify the open resource.

A file descriptor is valid only while it remains open. It should be
closed when it is no longer needed.

============================================================ 2. FILE AND
DIRECTORY CONCEPTS
============================================================

  ---------------------
  2.1 What is a File?
  ---------------------

A file is a named collection of information stored on a storage device.
A file may contain text, program instructions, images, audio, or other
data.

Common file types in Unix-like systems include: - Regular file: stores
ordinary data. - Directory: stores directory entries that associate
names with files. - Symbolic link: stores a path referring to another
file or directory. - Character device: provides character-oriented
device access. - Block device: provides block-oriented device access. -
FIFO: a named pipe used for inter-process communication. - Socket: an
endpoint for communication between processes.

The assignment’s mystat task needs to report at least regular files,
directories, and symbolic links.

  --------------------------
  2.2 What is a Directory?
  --------------------------

A directory is a file-system object that contains entries. Each entry
associates a file name with a file-system object.

Directories make it possible to organize files hierarchically. A
directory can contain ordinary files and subdirectories.

Special directory entries: - “.” refers to the current directory. - “..”
refers to the parent directory. - Names beginning with “.” are
conventionally treated as hidden by many Unix command-line tools. They
are not a separate file type.

  -------------------
  2.3 File Metadata
  -------------------

Metadata is information that describes a file rather than the actual
contents of the file.

Important metadata includes: - File type - File size - Inode number -
Number of hard links - Permissions - Owner and group identifiers - Last
access time - Last modification time - Last status-change time

The stat() function obtains file metadata and stores it in a struct stat
structure.

============================================================ 3. TASK 1 –
CUSTOM COPY COMMAND (mycp)
============================================================

  ---------
  3.1 Aim
  ---------

To implement a simple file-copying program in C using low-level POSIX
file operations.

The program receives a source path and a destination path. It reads
bytes from the source file and writes those bytes to the destination
file.

  ----------------------------
  3.2 Theory of File Copying
  ----------------------------

Copying a file means creating or replacing a destination file and
transferring the source file’s contents into it.

The basic process is: 1. Open the source file for reading. 2. Open or
create the destination file for writing. 3. Read a portion of the source
into a memory buffer. 4. Write the bytes read into the destination. 5.
Repeat until the end of the source file is reached. 6. Close both files.

A buffer is a temporary memory area used to hold data during transfer. A
buffer avoids the need to process the entire file at once. For example,
a 1024-byte buffer can be reused repeatedly until the file has been
copied.

  ---------------------
  3.3 open() Function
  ---------------------

Purpose: Opens a file and returns a file descriptor.

Header: #include <fcntl.h> #include <sys/types.h> #include <sys/stat.h>

General form: int open(const char *pathname, int flags, …);

Important flags: - O_RDONLY: open for reading only. - O_WRONLY: open for
writing only. - O_RDWR: open for both reading and writing. - O_CREAT:
create the file if it does not exist. - O_TRUNC: truncate an existing
regular file to zero length when opened for writing. - O_APPEND: make
writes occur at the end of the file.

For the source: open(source_file, O_RDONLY);

For the destination: open(destination_file, O_WRONLY | O_CREAT |
O_TRUNC, 0644);

The permission value 0644 is octal: - Owner: read and write (6). -
Group: read only (4). - Others: read only (4).

Important: the process umask may remove some requested permission bits.
The mode argument is used when O_CREAT creates a new file; it does not
reset the permissions of an existing file.

Return value: - Success: a non-negative file descriptor. - Failure: -1,
with errno set.

  ---------------------
  3.4 read() Function
  ---------------------

Purpose: Reads bytes from an open file descriptor into a memory buffer.

Header: #include <unistd.h>

General form: ssize_t read(int fd, void *buffer, size_t count);

Parameters: - fd: file descriptor to read from. - buffer: memory area
where the bytes will be stored. - count: maximum number of bytes to
read.

Return value: - Positive value: number of bytes actually read. - 0: end
of file (EOF). - -1: error.

A read() call is not guaranteed to return the full number of bytes
requested. The program should use the returned byte count.

  ----------------------
  3.5 write() Function
  ----------------------

Purpose: Writes bytes from a memory buffer to an open file descriptor.

Header: #include <unistd.h>

General form: ssize_t write(int fd, const void *buffer, size_t count);

Parameters: - fd: file descriptor to write to. - buffer: memory
containing the bytes to write. - count: number of bytes requested.

Return value: - Positive value: number of bytes actually written. - -1:
error.

A write() call can write fewer bytes than requested. A robust copy
program must continue writing until all bytes read from the source have
been written. It must also handle errors and avoid an infinite loop if
write() returns zero unexpectedly.

  ----------------------
  3.6 close() Function
  ----------------------

Purpose: Releases an open file descriptor.

Header: #include <unistd.h>

General form: int close(int fd);

Return value: - 0: success. - -1: failure.

Closing files releases process resources. A program should close every
descriptor it successfully opened, including when a later operation
fails.

  -----------------------
  3.7 perror() Function
  -----------------------

Purpose: Prints a descriptive error message associated with the current
errno value.

Header: #include <stdio.h>

Example: perror(“open”);

If opening a source file fails because the file does not exist, perror()
may print a message such as: open: No such file or directory

The exact message depends on the error and system language.

  ------------------------
  3.8 Algorithm for mycp
  ------------------------

1.  Start.
2.  Check that exactly two command-line arguments are provided after the
    program name.
3.  Open the source file using O_RDONLY.
4.  If opening fails, print the error using perror() and terminate.
5.  Open the destination using O_WRONLY | O_CREAT | O_TRUNC with mode
    0644.
6.  If destination opening fails, report the error, close the source
    descriptor, and terminate.
7.  Create a buffer of 1024 bytes.
8.  Repeatedly call read() on the source.
9.  If read() returns a positive number, write all those bytes to the
    destination. Handle partial writes.
10. If read() returns zero, the end of the file has been reached.
11. If read() or write() fails, report the error.
12. Close all descriptors that were opened.
13. Exit.

  ---------------------------
  3.9 Important Precautions
  ---------------------------

-   Check the number of command-line arguments.
-   Check every open(), read(), and write() result.
-   Do not assume one write() call writes all requested bytes.
-   Close the source if destination opening fails.
-   Do not use the same source and destination path: opening the
    destination with O_TRUNC could destroy the source contents.
-   A production-quality copy utility may also need to preserve
    metadata, handle special files, and define behavior for symbolic
    links. This assignment asks for a basic regular-file copy.

============================================================ 4. TASK 2 –
FILE METADATA EXTRACTOR (mystat)
============================================================

  ---------
  4.1 Aim
  ---------

To write a C program that retrieves and displays information about a
file or directory using the stat() system call interface.

  ----------------------------
  4.2 What is File Metadata?
  ----------------------------

File metadata is descriptive information maintained by the file system.
It helps the operating system and users identify a file, determine its
size, inspect permissions, and track changes.

The stat() function obtains metadata about a path and fills a struct
stat object.

  ---------------------
  4.3 stat() Function
  ---------------------

Headers: #include <sys/types.h> #include <sys/stat.h> #include
<unistd.h>

General form: int stat(const char pathname, struct stat statbuf);

Parameters: - pathname: path of the file or directory. - statbuf:
address of a struct stat variable where information is stored.

Return value: - 0: success. - -1: failure.

Example declaration: struct stat file_info;

The fields requested in this assignment include: - st_mode - st_size -
st_ino - st_nlink - st_mtime

  ------------------------
  4.4 struct stat Fields
  ------------------------

1.  st_mode Contains the file type and permission bits.

2.  st_size File size in bytes. For regular files, this is the number of
    bytes in the file. For other types, its meaning can vary.

3.  st_ino Inode number identifying the file-system object within its
    file system.

4.  st_nlink Number of hard links to the object.

5.  st_mtime Time of last data modification, represented as a time
    value.

Other useful fields include st_uid (owner user ID), st_gid (group ID),
st_atime (last access time), and st_ctime (last status-change time).

  -----------------------
  4.5 What is an Inode?
  -----------------------

An inode is a file-system data structure that stores information about a
file-system object, such as its type, permissions, owner, size,
timestamps, and references to its data blocks.

A directory entry maps a file name to an inode. The file name is not
generally stored as part of the inode itself.

Inode numbers are unique within a particular file system, but they are
not necessarily globally unique across all mounted file systems.

  ----------------
  4.6 Hard Links
  ----------------

A hard link is an additional directory entry that refers to the same
inode as another name.

Characteristics: - Multiple hard-link names refer to the same underlying
file-system object. - Changes made through one name are visible through
the others. - The link count is represented by st_nlink. - Removing one
name does not remove the object while other hard links remain. - Hard
links generally cannot be created for directories by ordinary users, and
cannot normally cross file-system boundaries.

  --------------------
  4.7 Symbolic Links
  --------------------

A symbolic link is a special file containing a path that refers to
another file or directory.

Unlike a hard link, a symbolic link has its own inode and can refer to a
path on another file system. It can also become dangling if its target
is removed or renamed.

Important distinction: - stat(path) follows a symbolic link and reports
information about its target. - lstat(path) reports information about
the symbolic link itself.

Therefore, if mystat must identify a symbolic link itself, use lstat()
rather than stat(). The assignment specifically asks for stat(), so a
program using stat() will normally report the target’s type when the
supplied path is a symbolic link.

  ------------------------
  4.8 Checking File Type
  ------------------------

The st_mode field contains both file-type and permission bits. POSIX
provides macros to test the type:

-   S_ISREG(st_mode): regular file.
-   S_ISDIR(st_mode): directory.
-   S_ISLNK(st_mode): symbolic link.
-   S_ISCHR(st_mode): character device.
-   S_ISBLK(st_mode): block device.
-   S_ISFIFO(st_mode): FIFO.
-   S_ISSOCK(st_mode): socket.

For a symbolic link itself, use the S_ISLNK test on the result of
lstat().

  ----------------------
  4.9 File Permissions
  ----------------------

Permissions control who can read, write, or execute a file.

There are three permission groups: - User/owner - Group - Others

There are three basic permission types: - Read (r): permission to
read. - Write (w): permission to modify. - Execute (x): permission to
execute a file or search a directory.

The octal permission digits are: - 4 = read - 2 = write - 1 = execute

Common examples: - 0644 = rw-r–r– - 0755 = rwxr-xr-x - 0600 = rw——- -
0700 = rwx——

Permission macros: - S_IRUSR, S_IWUSR, S_IXUSR - S_IRGRP, S_IWGRP,
S_IXGRP - S_IROTH, S_IWOTH, S_IXOTH

A string such as -rw-r–r– uses the first character to indicate the file
type and the remaining nine characters to show permissions for owner,
group, and others.

  -----------------------------
  4.10 File Modification Time
  -----------------------------

The st_mtime field stores the time when the file’s contents were last
modified.

It can be converted into a readable date and time using: - localtime()
to convert to local calendar time. - strftime() to format the date and
time as text.

The modification time is different from: - atime: last access time. -
ctime: last status change time, such as a metadata or permission change.
It is not the file creation time.

  ---------------------------
  4.11 Algorithm for mystat
  ---------------------------

1.  Start.
2.  Check that one path argument is provided.
3.  Declare a struct stat variable.
4.  Call stat(path, &file_info).
5.  If the call fails, display the error using perror() and terminate.
6.  Check st_mode using S_ISREG(), S_ISDIR(), and other suitable macros.
7.  Print file type.
8.  Print st_size in bytes.
9.  Print st_ino.
10. Print st_nlink.
11. Print permissions in octal or string form.
12. Convert st_mtime into a readable date and time and print it.
13. Exit.

============================================================ 5. TASK 3 –
BASIC DIRECTORY LISTER (myls)
============================================================

  ---------
  5.1 Aim
  ---------

To create a simple directory-listing program in C using opendir(),
readdir(), and closedir().

  -------------------------
  5.2 Directory Traversal
  -------------------------

Directory traversal means reading the entries stored in a directory. A
directory may contain files, subdirectories, and special entries such as
“.” and “..”.

A directory stream provides a way to read entries one at a time. POSIX
provides directory-handling functions in the dirent interface.

Header: #include <dirent.h>

  ------------------------
  5.3 opendir() Function
  ------------------------

Purpose: Opens a directory and returns a pointer to a directory stream.

General form: DIR opendir(const char name);

Parameter: - name: path of the directory to open.

Return value: - Success: pointer to a DIR stream. - Failure: NULL.

If it fails, perror() can be used to display the reason.

  ------------------------
  5.4 readdir() Function
  ------------------------

Purpose: Reads the next entry from an open directory stream.

General form: struct dirent readdir(DIR dirp);

It returns a pointer to a struct dirent containing information about the
next directory entry.

Important member: - d_name: name of the entry.

Return value: - Pointer to an entry when an entry is available. - NULL
when the end is reached or an error occurs.

A robust program should distinguish end-of-directory from an error by
setting errno to zero before the loop and checking errno if readdir()
returns NULL.

  -------------------
  5.5 struct dirent
  -------------------

struct dirent represents a directory entry returned by readdir().

The most commonly used field in this assignment is: - d_name: the
entry’s name.

Other fields may be available depending on the operating system and file
system, but portable programs should not assume every implementation
provides the same extra fields.

  ------------------
  5.6 Hidden Files
  ------------------

In Unix-like systems, file names beginning with a dot are conventionally
hidden from normal directory listings.

Examples: - .config - .profile - .local

The names “.” and “..” also begin with a dot. A basic listing program
should normally skip all names beginning with “.” unless the optional -a
flag is implemented.

The -a option conventionally means show all entries, including hidden
entries.

  -------------------------
  5.7 closedir() Function
  -------------------------

Purpose: Closes a directory stream opened by opendir().

General form: int closedir(DIR *dirp);

Return value: - 0: success. - -1: failure.

The directory stream should be closed after traversal to release
resources.

  ------------------------
  5.8 Algorithm for myls
  ------------------------

1.  Start.
2.  If a directory path is supplied, use it. Otherwise, use “.” (current
    directory).
3.  Call opendir() with the selected path.
4.  If opendir() returns NULL, display the error using perror() and
    terminate.
5.  Repeatedly call readdir() to obtain directory entries.
6.  For each entry, inspect d_name.
7.  Skip names beginning with “.” unless the -a option is enabled.
8.  Print the remaining names.
9.  After reaching the end, check for a readdir() error if implementing
    robust error handling.
10. Call closedir().
11. Exit.

  --------------------------------------
  5.9 Current Directory and Path Names
  --------------------------------------

A path identifies the location of a file or directory.

Absolute path: Begins at the root directory, represented by “/”.

Example: /home/student/documents

Relative path: Interpreted from the process’s current working directory.

Examples: - notes.txt - ./documents - ../downloads

The special path “.” means the current working directory. The special
path “..” means the parent directory.

============================================================ 6. TASK 4 –
INDEXED FILE ALLOCATION SIMULATION
============================================================

  ---------
  6.1 Aim
  ---------

To simulate Indexed File Allocation, a file-allocation technique in
which each file has a separate index block containing the addresses of
its data blocks.

  ------------------------------
  6.2 What is File Allocation?
  ------------------------------

File allocation is the method used by an operating system to assign
physical disk blocks to the data belonging to a file.

A file may occupy one or many disk blocks. The file system must keep
track of which blocks belong to each file so that it can retrieve the
file’s contents.

Common file-allocation methods: 1. Contiguous allocation 2. Linked
allocation 3. Indexed allocation

  ---------------------------
  6.3 Contiguous Allocation
  ---------------------------

In contiguous allocation, all blocks of a file are stored next to one
another on disk.

Example: If a file needs four blocks, it might be allocated blocks 20,
21, 22, and 23.

Advantages: - Simple to implement. - Fast sequential access. - Fast
direct access because block locations can be calculated.

Disadvantages: - External fragmentation can occur. - The file’s required
size may need to be known in advance. - Growing a file can be difficult
if the following blocks are already occupied.

  -----------------------
  6.4 Linked Allocation
  -----------------------

In linked allocation, a file is stored as a linked list of disk blocks.
Each block contains data and a pointer to the next block.

Example: Block 7 -> Block 19 -> Block 42 -> Block 61

Advantages: - Blocks do not need to be contiguous. - Files can grow by
adding another free block. - External fragmentation is avoided.

Disadvantages: - Direct/random access is slow because pointers must be
followed. - A pointer in each block consumes some storage. - A damaged
pointer can break the chain.

  ------------------------
  6.5 Indexed Allocation
  ------------------------

In indexed allocation, each file has an index block. The index block
stores the addresses (block numbers) of the data blocks belonging to
that file.

The file’s data blocks can be located anywhere on the disk. They do not
need to be contiguous.

Example: Suppose a file needs four data blocks: - Index block: 10 - Data
blocks: 5, 18, 37, 62

The index block stores: [5, 18, 37, 62]

The operating system uses the index block to find the file’s data
blocks.

  ----------------------------------
  6.6 How Indexed Allocation Works
  ----------------------------------

1.  A file is created.
2.  The operating system finds a free disk block for the file’s index
    block.
3.  It finds enough additional free blocks for the file’s data.
4.  The block numbers of the data blocks are stored in the index block.
5.  The index block and data blocks are marked as allocated.
6.  When the file is accessed, the system reads the index block to
    locate the required data blocks.

The index block acts as a table of pointers. It does not normally
contain the file’s actual user data; it contains addresses of the data
blocks.

  --------------------------------------
  6.7 Advantages of Indexed Allocation
  --------------------------------------

-   Data blocks can be located anywhere on the disk.
-   External fragmentation is avoided.
-   Supports direct/random access because the address of a data block
    can be found through the index.
-   File growth is easier than with contiguous allocation, provided free
    blocks and index capacity are available.

  -----------------------------------------
  6.8 Disadvantages of Indexed Allocation
  -----------------------------------------

-   An index block consumes extra disk space.
-   Small files may waste space in their index blocks.
-   A file’s maximum size may be limited by the number of pointers that
    fit in its index block, unless multi-level indexing is used.
-   Accessing data may require reading the index block first, unless it
    is already cached.
-   If the index block is damaged, locating the file’s data blocks may
    become difficult.

  ------------------------------------------
  6.9 Disk Block and Free-Space Management
  ------------------------------------------

A disk can be viewed as a collection of fixed-size blocks. In this
assignment, the simulated disk has 100 blocks numbered 0 through 99.

The array: int disk[100];

represents the allocation status of each block.

Meaning: - disk[i] = 0: block i is free. - disk[i] = 1: block i is
allocated.

When a file is created, its index block and all of its data blocks must
be marked as allocated.

The simulation must never allocate a block that is already in use.

  ------------------------------
  6.10 Random Block Allocation
  ------------------------------

The assignment asks the program to choose free blocks randomly.

A typical approach is: 1. Generate a random block number in the range 0
to 99. 2. Check whether that block is free. 3. If it is free, allocate
it. 4. If it is already allocated, try another candidate. 5. Continue
until the index block and all required data blocks have been found, or
until it is clear that there is not enough free space.

In C, rand() can generate pseudo-random numbers. srand() is commonly
called once near the beginning of the program to seed the random-number
generator.

Example: srand((unsigned int)time(NULL));

Headers: #include <stdlib.h> #include <time.h>

A safer allocation design first counts the free blocks. If fewer than
(number of requested data blocks + 1) are free, it reports insufficient
space without partially allocating the file.

For a simple simulation, another reliable approach is to build a list of
free block numbers, shuffle it, and take the required number from the
shuffled list. This avoids repeatedly selecting blocks that are already
occupied.

  ---------------------------------------------
  6.11 File Directory Table in the Simulation
  ---------------------------------------------

The simulated directory stores information about every file created.

For each file, store: - File ID - Index block number - Number of data
blocks - List of allocated data block numbers

This information can be represented using a structure in C.

For example, a structure may contain: - an integer file_id - an integer
index_block - an integer block_count - an array of data block numbers

The directory table is a simulation of file-system bookkeeping. It
allows the Display Directory option to show the allocation information
for each created file.

  -----------------------------------
  6.12 Insufficient Space Condition
  -----------------------------------

A file requiring N data blocks needs N + 1 free disk blocks because it
also needs one index block.

For example: - Requested data blocks = 6 - Required total free blocks =
7

If the disk has fewer than 7 free blocks, allocation must fail and the
program should display: Insufficient space

The program should check this before marking any blocks as allocated.
This prevents a failed file creation from leaving blocks incorrectly
reserved.

The program should also validate that the requested block count is
positive and that the directory table has room for another file.

  --------------------------------------------
  6.13 Algorithm for Indexed File Allocation
  --------------------------------------------

Initialization: 1. Start. 2. Initialize disk[100] to zero. 3. Initialize
the file directory table as empty. 4. Display the menu.

Create File: 1. Read the File ID. 2. Read the required number of data
blocks. 3. Validate the input. 4. Count the free blocks. 5. If fewer
than N + 1 blocks are free, print “Insufficient space”. 6. Otherwise,
randomly select one free block for the index block. 7. Randomly select N
other free blocks for data. 8. Store the data block numbers in the
file’s directory record, representing the index-block contents. 9. Mark
the index block and data blocks as allocated. 10. Add the file record to
the directory table. 11. Return to the menu.

Display Directory: 1. Visit each file record in the directory table. 2.
Print its File ID. 3. Print its index block number. 4. Print the list of
data block numbers. 5. Return to the menu.

Exit: 1. Terminate the program.

  ------------------------------------
  6.14 Example of Indexed Allocation
  ------------------------------------

Assume a file has ID 101 and requires 3 data blocks.

One possible allocation is: - Index block: 14 - Data block 1: 8 - Data
block 2: 45 - Data block 3: 72

The index-block contents are: 8, 45, 72

The directory display could look like:

File ID: 101 Index Block: 14 Data Blocks: 8 45 72

This is only an example. Because the assignment requires random
allocation, actual block numbers may differ each time the program runs.

============================================================ 7.
IMPORTANT DIFFERENCES AND COMPARISONS
============================================================

  -----------------------------------
  7.1 System Calls and Standard I/O
  -----------------------------------

System-call interface: - Works with file descriptors. - Uses low-level
byte-oriented operations such as read() and write(). - Gives direct
control over file operations. - Requires the programmer to handle
partial reads and writes.

Standard I/O: - Works with FILE pointers. - Uses functions such as
fopen(), fread(), fwrite(), and fclose(). - Provides buffering and
convenient formatted I/O. - Often requires less low-level handling.

  ------------------------
  7.2 stat() vs. lstat()
  ------------------------

stat(): - Follows a symbolic link. - Reports metadata about the link’s
target.

lstat(): - Does not follow the final symbolic link. - Reports metadata
about the symbolic link itself.

This distinction matters when identifying symbolic links.

  ---------------------------------
  7.3 Hard Link vs. Symbolic Link
  ---------------------------------

Hard link: - Refers to the same inode as another directory entry. -
Usually cannot cross file-system boundaries. - Normally cannot be made
for directories by ordinary users. - Continues to access the object as
long as at least one hard link remains.

Symbolic link: - Has its own inode. - Stores a target path. - Can cross
file-system boundaries. - Can point to a directory. - Can become
dangling if the target path no longer exists.

  --------------------------------------------------
  7.4 Contiguous vs. Linked vs. Indexed Allocation
  --------------------------------------------------

Contiguous allocation: - Stores file blocks next to each other. - Offers
good sequential and direct access. - Can suffer from external
fragmentation and difficult file growth.

Linked allocation: - Connects file blocks using pointers. - Supports
easy growth and avoids external fragmentation. - Makes direct access
slower.

Indexed allocation: - Stores data-block addresses in an index block. -
Supports direct access and avoids the need for contiguous blocks. -
Requires extra space for index information.

============================================================ 8. COMMON
ERRORS AND PRECAUTIONS
============================================================

1.  Missing command-line arguments: Check argc before using argv
    entries.

2.  File not found: open() or stat() may fail. Use perror().

3.  Permission denied: The process may not have sufficient permissions
    to access a file or directory.

4.  Invalid directory: opendir() returns NULL if the path cannot be
    opened as a directory.

5.  Partial read: read() may return fewer bytes than requested. Use the
    returned count.

6.  Partial write: write() may write fewer bytes than requested.
    Continue until all bytes have been written or an error occurs.

7.  Resource leaks: Close every successfully opened file descriptor and
    directory stream.

8.  Symbolic-link confusion: stat() follows a symbolic link; lstat()
    examines the link itself.

9.  Disk allocation error: Never allocate an already-used block. Check
    for enough free blocks before committing an allocation.

10. Duplicate File IDs: A simulation should decide whether duplicate IDs
    are allowed. A sensible design rejects an ID that is already
    present.

11. Invalid block count: Reject zero or negative block counts and
    requests larger than the available disk capacity.

12. Random selection: Seed the random-number generator once, not every
    time a block is selected.

============================================================ 9. SHORT
VIVA / EXAM QUESTIONS WITH ANSWERS
============================================================

Q1. What is a system call? Answer: A system call is an interface through
which a user program requests a service from the operating-system
kernel.

Q2. What is the purpose of open()? Answer: open() opens a file and
returns a file descriptor.

Q3. What does O_RDONLY mean? Answer: It opens a file in read-only mode.

Q4. What is the purpose of O_CREAT? Answer: It creates the destination
file if it does not already exist.

Q5. What does O_TRUNC do? Answer: When opening an existing regular file
for writing, it reduces its length to zero.

Q6. What does 0644 mean? Answer: The owner has read and write
permission, while the group and others have read permission.

Q7. What does read() return at the end of a file? Answer: It returns
zero.

Q8. Can write() write fewer bytes than requested? Answer: Yes. The
program must handle partial writes.

Q9. Why is close() important? Answer: It releases an open file
descriptor and associated resources.

Q10. What is a file descriptor? Answer: It is a non-negative integer
used by a process to refer to an open file or I/O resource.

Q11. What is perror() used for? Answer: It prints a descriptive message
for the most recent error indicated by errno.

Q12. What is file metadata? Answer: Metadata is information describing a
file, such as its size, permissions, inode number, and timestamps.

Q13. What is stat() used for? Answer: It obtains metadata about a path
and stores it in a struct stat.

Q14. What is an inode? Answer: An inode is a file-system data structure
containing information about a file-system object.

Q15. What is st_size? Answer: It gives the file size in bytes for a
regular file.

Q16. What is st_ino? Answer: It contains the inode number.

Q17. What is st_nlink? Answer: It contains the number of hard links to
the object.

Q18. What is the difference between stat() and lstat()? Answer: stat()
follows a symbolic link and reports its target; lstat() reports the link
itself.

Q19. What is a hard link? Answer: It is another directory entry
referring to the same inode.

Q20. What is a symbolic link? Answer: It is a special file that stores a
path to another file or directory.

Q21. What is a directory? Answer: A directory is a file-system structure
containing entries that associate names with file-system objects.

Q22. What is opendir() used for? Answer: It opens a directory stream for
reading.

Q23. What is readdir() used for? Answer: It reads the next entry from a
directory stream.

Q24. What does d_name contain? Answer: It contains the name of a
directory entry.

Q25. What does closedir() do? Answer: It closes an open directory
stream.

Q26. Why are files beginning with a dot called hidden files? Answer:
Unix-like command-line conventions normally omit names beginning with a
dot from ordinary listings.

Q27. What does “.” represent? Answer: The current directory.

Q28. What does “..” represent? Answer: The parent directory.

Q29. What is file allocation? Answer: It is the method used by a file
system to assign disk blocks to files.

Q30. Name the three common file-allocation methods. Answer: Contiguous,
linked, and indexed allocation.

Q31. What is indexed allocation? Answer: It is a method in which an
index block stores the addresses of a file’s data blocks.

Q32. What is an index block? Answer: It is a block containing pointers
or addresses of the data blocks belonging to a file.

Q33. Do indexed-allocation data blocks need to be contiguous? Answer:
No. They can be located anywhere among the free disk blocks.

Q34. What is the main advantage of indexed allocation? Answer: It
supports direct access to data blocks and avoids the need for contiguous
allocation.

Q35. What is a disadvantage of indexed allocation? Answer: It requires
additional storage for the index block.

Q36. Why does a file need one extra block in this simulation? Answer: It
needs one index block in addition to its requested data blocks.

Q37. If a file requires 5 data blocks, how many total blocks must be
allocated? Answer: 6 blocks: one index block and five data blocks.

Q38. What does disk[i] = 0 mean? Answer: Disk block i is free.

Q39. What does disk[i] = 1 mean? Answer: Disk block i is allocated.

Q40. When should the program display “Insufficient space”? Answer: When
the number of free blocks is less than the requested data blocks plus
one index block.
